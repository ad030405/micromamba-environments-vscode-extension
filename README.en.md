# Micromamba Environments

[中文](./README.md) | English

> [!NOTE]
> This project was generated by AI.

Manage Micromamba environments and packages in VS Code, and select the actual interpreter used by the Python extension.

This desktop / Remote extension is written in TypeScript. The initial release targets Windows, Linux, and macOS, with Windows PowerShell and local Micromamba environments as the primary validation targets.

## Installation and usage

Requires VS Code **1.110 or later**, an existing Micromamba installation, and Microsoft's **[Python](https://marketplace.visualstudio.com/items?itemName=ms-python.python)** and **[Python Environments](https://marketplace.visualstudio.com/items?itemName=ms-python.vscode-python-envs)** extensions. Install **[Pylance](https://marketplace.visualstudio.com/items?itemName=ms-python.vscode-pylance)** for completion, import resolution, and type checking, and **[Python Debugger](https://marketplace.visualstudio.com/items?itemName=ms-python.debugpy)** for debugging. Python and Python Environments are extension dependencies; VS Code handles their installation.

1. Search for `Micromamba Environments` in the Extensions view, or [install it from the Marketplace](https://marketplace.visualstudio.com/items?itemName=ad070809.micromamba-environments).
2. Reload the window and open the **Micromamba** panel on the left.
3. If no environments are found, search for `@ext:ad070809.micromamba-environments` in Settings, configure the executable path and root prefix, then refresh.
4. Click an environment name or the ✓ icon next to it to select the interpreter for the current workspace. You can also switch using the Python extension's interpreter selector in the lower-right corner or the official Python Environments panel. In a multi-folder workspace, you will be prompted to choose the target folder.
5. Use **Python: Run Python File in Terminal**, Pylance, and Python Debugger as usual. The editor's existing Run dropdown also includes **Run Python File with Micromamba**, which runs the file in the selected environment and displays output in a Task terminal. This command appears when the current file uses a Micromamba Python environment and is also available from the Command Palette. New terminals load the selected environment for their folder silently by default, without displaying the activation script.

Your selection is saved per project directory and restored when you reopen the folder, reload the window, or open a `.code-workspace` containing that folder. Records live in VS Code's private storage; records from older versions are migrated automatically.

Opening a project or a Python file and discovering environments do not automatically bind Micromamba or create `.vscode/settings.json`. When you explicitly select an environment for a project, the official Python Environments extension writes `python-envs.defaultEnvManager` and `python-envs.defaultPackageManager`. Restoring a saved project selection may also restore these settings. Existing settings from older versions are kept; for a project without a saved Micromamba choice, you can review and remove those two entries manually while keeping other settings. If the project previously used Micromamba, switch to another provider through the official interpreter selector first to clear its saved record.

Example Windows configuration (replace the paths with your own installation locations):

```json
{
  "micromamba.executablePath": "D:\\develop\\micromamba\\micromamba.exe",
  "micromamba.rootPrefix": "D:\\develop\\micromamba",
  "micromamba.autoActivateTerminal": true,
  "python.useEnvironmentsExtension": true
}
```

When the executable path is empty, the extension checks `MAMBA_EXE`, `PATH`, and common locations under `MAMBA_ROOT_PREFIX`, in that order. The root prefix can also be obtained from `micromamba info --json`. Paths support `~`, `${env:VARIABLE}`, and `%VARIABLE%`. If micromamba is available only as a PowerShell function and is not on PATH, configure the path to the actual `.exe` file.

## Features

- A dedicated sidebar showing environments, Python versions, and the current project selection. Packages are loaded on demand when an environment is expanded, with pip packages marked separately.
- Create named environments, specify a Python version, and choose initial packages. Import `environment.yml`, and export a complete YAML file or Conda installation history.
- Install / uninstall Conda packages and update all Conda packages through Micromamba. Install / uninstall PyPI packages through the environment's `python -m pip`.
- Register environment and package managers with Microsoft's Python Environments extension, making micromamba environments available in the official environment panel and interpreter selector. The environment manager is displayed with an icon and the name **Micromamba**.
- Select project interpreters through the official `setEnvironment` API.
- Keep environment objects and IDs stable across reads and refreshes for the same interpreter. After the official selection flow commits, synchronize the legacy API cache through the Python extension's public `updateActiveEnvironmentPath` API. Python validation requests without a resource path can fall back to the current project selection.
- Use `micromamba run --prefix … <python>` for the official run flow's `activatedRun`, providing the environment variables and dynamic library paths needed at runtime.
- Run the Micromamba command in the existing Run dropdown through `micromamba run`, using the actual interpreter and displaying output in VS Code's Task panel. The working directory is the file's workspace root, or its containing directory when no workspace is open.
- Provide an interpreter and activation environment variables for Python **launch** debug configurations that do not explicitly specify an interpreter. The user's `python` / `pythonPath` and `env` values in `launch.json` take precedence.
- Inject activation variables and PATH obtained from `micromamba run` into new terminals through VS Code's environment variable collections, scoped to each workspace folder. No activation command is sent, and the terminal is not cleared or its history removed. You can also open an activated terminal or activate an existing terminal manually.
- Persist project selections by directory URI in VS Code's private storage without writing interpreter paths to project settings. Restore only projects in the current workspace, with independent choices for each folder. Temporary unset states during startup do not erase records; unavailable environments keep their records and produce a log message. Switching to an interpreter from another provider clears that project's Micromamba choice and stops automatic terminal activation using the old environment.

Creation and installation operations show progress and live logs and can be cancelled. Changes to the same environment are queued. Deleting environments and uninstalling packages require confirmation in the extension UI; deletion of the base root environment is blocked. Cancellation cannot undo changes micromamba has already completed.

Separate package specifications with spaces, for example, `numpy pandas>=2 conda-forge::scipy`. A comma in a version range belongs to the same specification, as in `numpy>=1.26,<3`. pip extras such as `requests[socks]` are supported. Arbitrary pip options, URLs, and requirements files are not currently supported in the input box.

## Settings

| Setting | Default | Purpose |
| --- | --- | --- |
| `micromamba.executablePath` | Empty | Full path to the micromamba executable |
| `micromamba.rootPrefix` | Empty | Root prefix for environments |
| `micromamba.channels` | `["conda-forge"]` | Channels used for creation, Conda installation, and updates; micromamba's own configuration is also respected |
| `micromamba.autoActivateTerminal` | `true` | Automatically activate new regular terminals |
| `micromamba.terminalActivationMode` | `silent` | `silent` injects variables before the process starts; `command` uses the shell hook / activation command |
| `micromamba.terminalActivationDelay` | `1500` | Startup delay in milliseconds for terminals without shell integration when using command mode or manual activation |
| `micromamba.commandTimeout` | `60` | Timeout in seconds for read-only commands; this timeout does not apply to mutation operations |

## Local development

```powershell
npm install
npm run check
npm test
npm run package
```

Use Node.js 22.21.1 or later. TypeScript is compiled before packaging, and the VSIX is written to `dist/`. If nvm's active version only takes effect in a new session, restart VS Code or run `nvm use 24.21.0` first.

Open this project in VS Code, press **F5**, and select the launch configuration named “运行 Micromamba 插件” (“Run Micromamba Extension”). VS Code compiles the project and opens a separate **Extension Development Host** window running the development version of the extension. Open a Python project there to test the sidebar, interpreter selection, and terminals.

Source overview:

| File | Responsibility |
| --- | --- |
| `package.json` | Extension manifest, commands, sidebar, menus, settings, and dependencies |
| `src/extension.ts` | Extension entry point and user action flows |
| `src/micromamba.ts` | Locate micromamba, execute its CLI, read environments and packages, and serialize mutations |
| `src/pythonBridge.ts` | Official environment / package managers, interpreter selection, execution information, and debug configuration |
| `src/selection.ts` | Persist selections per project |
| `src/tree.ts` | Sidebar tree view |
| `src/terminals.ts` | Shell detection, startup readiness, and terminal activation |
| `src/core.ts`, `src/process.ts` | Data parsing, argument validation, shell quoting, and process execution |
| `src/i18n.ts`, `package.nls*.json`, `l10n/` | Localization adapter, manifest strings, runtime messages, and Chinese / English translations |
| `src/test/` | Unit tests and the isolated Extension Host integration test entry point |

When adding UI messages, use `%key%` in `package.json` to reference `package.nls.json` and the corresponding Chinese files. At runtime, use `t('English message {0}', value)` from `src/i18n.ts` and maintain `l10n/bundle.l10n*.json`. Use placeholders such as `{0}` and `{1}` so translations can reorder arguments. Keep brand names, package names, paths, command IDs, and setting keys unchanged. Reload the window after changing the IDE's display language to apply the translations.

For local Windows integration testing, run `./scripts/test-host.ps1 -Fresh`. It copies the installed Python-related extensions into `.tools/`, creates a fresh project with no interpreter selection or manager settings, and uses isolated user data to check first-time selection, actual execution / debugging / silent activation, and interpreter warnings in the Python logs. Without `-Fresh`, it uses the retained `test-workspace/` directory. Run `./scripts/test-restore.ps1` to check that the selection is restored after closing and reopening VS Code. The tests use the local `D:\develop\micromamba` installation and `pytorch` environment; on another machine, update the test configuration and the relevant path / environment assertions first. See `VERIFICATION.md` for detailed test results.

## Validation and scope

Run `./scripts/test-lifecycle.ps1` with isolated user data and fresh projects to check that no settings file is created before selection, along with first selection, close/reopen, window reload, opening through `.code-workspace`, multi-folder isolation, and reopening after switching providers. Test configuration lives in the isolated user directory, and projects have no `.vscode/` before selection. The script uses `pytorch` under the local `D:\develop\micromamba` installation and MSYS2's system Python; adjust paths and assertions on another machine.

Automated tests cover JSON compatibility, package source detection, directory boundaries, input validation, shell quoting, process execution without a shell, cancellation, and timeouts. Extension Host integration tests use isolated VS Code user data and test workspaces to check real micromamba environment registration, package lists, and interpreter selection in the Python extension. They do not create, delete, or modify existing Python environments.

For manual validation, select an environment and run the following code with both the official Python run command and the Micromamba command in the Run dropdown. Then run `python -c "import sys; print(sys.executable)"` in a new terminal. All three should use the selected environment:

```python
import sys
print(sys.executable)
print(sys.prefix)
```

Next, check that Pylance resolves installed packages and press F5 to verify debugging. If testing PyTorch, run `import torch; print(torch.__version__)`.

- The default silent mode injects the environment before a new terminal process starts. Python and `CONDA_PREFIX` point to the selected environment, but the prompt may not show `(environment-name)`, and micromamba shell functions are not installed. If you need the environment name in the prompt and the `micromamba activate` / `deactivate` shell functions, set `micromamba.terminalActivationMode` to `command` or use **Activate Current Terminal**. Environment variable collections are scoped to workspace folders; a file-level selection does not override the terminal environment for the entire folder. Recreate existing terminals to use a new selection.
- Command mode sends activation commands after shell integration is ready. Without integration, it uses the configured startup delay. Terminals with a detected command in progress, task terminals, custom PTYs, and debug consoles are skipped. Without integration, the extension cannot reliably detect a partially typed command. For slow or customized shell startup, increase the delay or disable automatic activation and activate manually.
- The additional terminal auto-activation behavior in Microsoft's Python Environments extension varies by version. If activation happens twice, set `python-envs.terminal.autoActivationType` to `off` and keep this extension's automatic activation enabled. The corresponding setting in the legacy Python extension is `python.terminal.activateEnvironment`.
- If `python.useEnvironmentsExtension` is disabled, the extension offers an **Enable and Reload** button. You can also enable it manually in Settings. This initial release depends on the modern Python Environments API and does not silently fall back to only changing the default interpreter path.
- Use PowerShell if a CMD path contains `%` or double quotes. Shell commands for Linux / macOS have argument quoting tests, but still require validation on those systems.
- An empty window can have its own environment selection. That selection is never a default for other projects, and files outside a workspace do not inherit selections from projects inside it. Multi-folder projects match terminals by cwd and files by their workspace folder. In Remote / WSL environments, the extension and micromamba must run on the same remote host; saved records distinguish URI schemes and remote hosts. The extension is disabled in virtual and untrusted workspaces.
- Notebook kernels are managed by the Jupyter extension. The initial release does not guarantee automatic switching of existing Notebook kernels; select the corresponding environment in the Notebook kernel picker.
- Other extensions, such as Code Runner, have separate execution settings. This extension integrates with Microsoft's Python execution / debugging flow.
